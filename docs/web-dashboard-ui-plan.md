# SALBAR Operator Web Dashboard: UI Specification and Design System

## Overview
This document specifies the screen architecture, interaction flows, and color system for the SALBAR (System for Allocation and LoRa-Linked Barangay Assessment and Response) Operator Web Dashboard. 

Designed for real-world disaster operations centers (Barangay and City Disaster Risk Reduction and Management Offices), this system prioritizes situational clarity, rapid decision-making, and high visual contrast during crisis conditions.

---

## Screen Architecture

The dashboard consolidates disaster response operations into three primary views and an ambient status header.

```
+---------------------------------------------------------------------------------------+
|  SALBAR EOC    [COM3: Online 915MHz]  [Mode: LoRa Mesh Blackout]  [Alerts: 4 Active]  |
+------------------------------------+--------------------------------+-----------------+
|  1. Command Map and Triage CAD     |  2. Field Responder Fleet      |  3. Incident    |
|     (Primary Live Operations)      |     (Status and Fatigue)       |     Archive     |
+------------------------------------+--------------------------------+-----------------+
```

### 1. Command Map and Triage CAD (Primary Mission Control)
The main operational view where the incident commander monitors incoming emergencies, visualizes responder positions, and authorizes dispatches.

- **Full-Height GIS Map (Left / Center Pane)**:
  - Interactive map supporting local cached offline vector/raster tiles (operates during complete external internet blackout).
  - **Incident Markers**: Color-coded and priority-scaled pins indicating reported hazards (Critical = Red, High = Orange, Medium = Amber, Low = Blue).
  - **Responder Markers**: Real-time position icons for the three field terminals (Search and Rescue, Damage Assessment, Relief Operations), showing heading, Kalman-smoothed coordinates, and current operational state.
  - **Hazard Overlays**: Visual flags indicating impassable routes, flooded roads, and debris barriers incorporated into the routing engine.
- **Live Incident Stream (Right Pane)**:
  - Continuously updating feed of incoming incident reports received via LoRa mesh or Cloud Relay.
  - Quick filter tabs: `All`, `Unassigned`, `Awaiting Review`, `Dispatched`, `Resolved`.
  - Report Card metadata: Urgency level, incident category, language detected, timestamp elapsed, and submission source (`BLE Relay`, `LoRa Direct`, `Cloud`).
- **Human-in-the-Loop (HITL) Dispatch Drawer / Modal**:
  - Opens upon selecting an unassigned or pending report:
    1. **Original Text and NLP Interpretation**: Displays original resident wording (in Cebuano, Tagalog, English, or code-switched text) alongside normalized English translation, detected landmark entities, and severity score.
    2. **AI Situation Briefing**: Concise summary generated by the propose-only AI agent outlining immediate needs, hazards, and victim count.
    3. **Google OR-Tools Allocation Proposal**: Recommended response team, predicted travel time, detour penalties, and projected responder fatigue index.
    4. **Commander Authorization Controls**:
       - `[Approve and Dispatch via LoRa]`: Encodes the command and queues it to the gateway serial connection for immediate over-the-air transmission.
       - `[Reject Proposal]`: Records the dismissal and keeps the report in pending queue without radio broadcast.
       - `[Manual Reassign]`: Allows manual operator override to select a different responder unit.

---

### 2. Field Responder Fleet Management (Team Status and Fatigue)
Monitors the physical condition, location reliability, and workload distribution of the three deployed response units.

- **Unit Cards (3 Deployed Terminals)**:
  - **Unit 1**: Search-and-Rescue (SAR)
  - **Unit 2**: Damage-Assessment (DA)
  - **Unit 3**: Relief Operations
- **Card Telemetry and Diagnostics**:
  - **Operational Status**: `Available`, `En Route`, `On Scene`, `Resting / Mandatory Break`, `Offline`.
  - **Active Assignment**: Target incident ID, GPS destination pin, and estimated arrival.
  - **Responder Fatigue Index**: Visual gauge tracking continuous mission duration, high-intensity task penalties, and recommended rest intervals.
  - **Hardware Metrics**: Battery percentage, supply voltage (from onboard AXP power chip), and GPS lock accuracy status.
  - **BLE Ingestion Counter**: Count of resident reports collected wirelessly and relayed across the LoRa mesh.
  - **Manual Status Controls**: Commander toggle to set a unit to `Mandatory Rest` or `Out of Service`.

---

### 3. Incident Archive and Audit History (Post-Disaster Log)
Dedicated record-keeping view supporting post-disaster evaluation, barangay relief auditing, and official government reporting (RDANA / NDRRMC compliance).

- **Search and Filter Table**:
  - Filterable by date, time range, purok/zone, incident type, and assigned unit.
  - Global search across raw civilian text, translations, and resolution notes.
- **Incident Audit Trail**:
  - Complete chronological record: Report ingestion timestamp -> AI/NLP classification -> Operator approval time -> Field arrival time -> Incident cleared time.
  - Identification of communication pathway used (`BLE opportunistic relay` vs `Direct Internet`).
- **Data Export**:
  - One-click export to CSV and formatted PDF summary for local government reporting.

---

### Ambient Status Header (Persistent System Health)
Eliminates the need for a separate hardware diagnostics screen by displaying vital hardware parameters in the persistent top bar:

- **LoRa Gateway Serial Bridge**: `Online (COM3 / 915 MHz)` (triggers immediate visual and audio warning if disconnected).
- **Network Operating Mode**: `Local Mesh Only (Outage)` vs `Cloud Sync Active`.
- **Active Incident Counter**: Ratio of active emergencies to resolved calls.
- **Audio Siren / Chime Toggle**: Audible notification on reception of high-urgency rescue calls.

## Color System and Design Tokens

The color palette is designed with an emergency dispatch aesthetic: a deep **Midnight Navy** background representing command-and-control authority, paired with high-visibility **Safety Orange** as the primary functional accent for critical actions and alerts.

### Dark Mode (Primary Operations Center Theme)
Optimized for low-light command centers, high visual comfort during prolonged 24/7 shifts, and maximum contrast on high-resolution displays.

| Token | Hex Value | Role and Usage |
| :--- | :--- | :--- |
| `bg-base` | `#0A0F1D` | Main application background (Deep Midnight Navy) |
| `bg-surface` | `#111C38` | Panels, sidebars, cards, and modal backdrops |
| `bg-surface-elevated` | `#18264B` | Hovered cards, dropdown menus, and elevated popovers |
| `border-subtle` | `#1F2E5C` | Inactive borders, dividers, and table row outlines |
| `border-focus` | `#334B85` | Focused inputs and highlighted panel borders |
| `text-primary` | `#F8FAFC` | Main headings, primary values, and incident titles |
| `text-secondary` | `#94A3B8` | Subtitles, timestamps, and secondary metadata |
| `text-muted` | `#64748B` | Inactive labels, disabled controls, and hints |
| `accent-primary` | `#FF6B00` | Primary CTA, approve dispatch button, and focus rings |
| `accent-hover` | `#FF8533` | Hover state for primary buttons |

## Typography Standards

### Font Families
- **Primary UI & Headings**: `Inter` (weights: 400, 500, 600, 700) with fallback `-apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, Helvetica, Arial, sans-serif`.
  - Open apertures and clean geometry engineered for high-density dashboard interfaces.
  - Enabled font features: `cv02`, `cv03`, `cv04`, `cv11` for high-clarity technical legibility.
- **Telemetry & Numerical Data (Monospace)**: `JetBrains Mono` (weights: 400, 500, 600) with fallback `ui-monospace, SFMono-Regular, Menlo, Monaco, Consolas, "Liberation Mono", monospace`.
  - Tabular numbers (`tnum`) ensure GPS coordinates, live counters, and timestamps do not shift layout on updates.
